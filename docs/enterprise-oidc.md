# 企业 OIDC 账号绑定

OIDC 登录以认证中心的 `issuer + sub` 绑定本地用户，绑定后邮箱变化不会创建第二个账号。首次登录没有绑定时，沿用邮箱匹配已有账号的行为；绑定只能由可信后端写入，不接受浏览器提交用户 ID。并发写入不能把身份改绑给另一用户。

对于由 AgentOS 在空间 10000 预先开通员工的部署，在服务端配置文件中设置：

```yaml
oidc_auth:
  existing_user_tenant_id: 10000
```

此设置禁止 OIDC 自动创建账号或个人空间。登录必须匹配有效员工，并具有该空间的有效成员关系，登录令牌和返回的当前空间均为 10000。尚未开通或邮箱不匹配的员工会收到联系管理员的提示。默认值 0 保留其他部署的自动注册策略；密码注册和邀请流程不受影响。

对于已经产生的重复账号，应先通过 AgentOS 的已绑定外部身份和认证中心的唯一 subject 确认归属，将 `user_oidc_identities` 中该 issuer/subject 绑定至原有员工 UUID。不能仅凭相同姓名或浏览器提交的邮箱合并账号。保留原员工的用户 ID、密码、成员关系和 API Key，以保留同步知识库的私有所有权。

重复账号停用前须检查其是否已有业务数据并备份对应记录。撤销重复账号的登录令牌后，用户重新点击飞书登录即可进入原账号；原账号的首次改密要求继续生效。绑定和成员权限分别检查，已移除成员不得借助旧绑定重新进入空间。

数据库迁移：PostgreSQL 95 / SQLite 17，新增独立绑定表，不改写现有用户或知识内容。回退应用时保留表和绑定数据；先关闭企业限制并评估旧版本的邮箱匹配行为，避免重新生成重复账号。
